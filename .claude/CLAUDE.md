# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`pyroll-core` is the core package of PyRolL v4 (a rewrite, currently alpha / proof of concept). It is at an early scaffolding stage: most modules are still empty, so check `docs/` for intended design before inventing structure.

## Environment & commands

The dev environment is managed by devenv (Nix) with Python 3.14 and uv (`.venv`, auto-synced on shell entry). Always run tools through uv.

```sh
uv sync                                   # install/update dependencies from uv.lock
uv add <pkg> / uv add --dev <pkg>         # add a dependency (never edit uv.lock by hand)
uv run pytest                             # run all tests
uv run pytest tests/path/test_x.py::test_name   # run a single test
uv run pytest -k "expr"                   # run tests matching an expression
uv run ruff check --fix .                 # lint
uv run ruff format .                      # format Python
treefmt                                   # format everything (ruff, nixfmt, taplo, yamlfmt, mdformat, just) — also `just format`
```

- treefmt runs as a pre-commit hook with `--fail-on-change`; run `treefmt` before committing. `.pre-commit-config.yaml` is generated by git-hooks.nix — do not edit it; change `devenv.nix` instead.
- The repo is colocated with Jujutsu (`.jj/`), so git may show a detached `HEAD`; that is expected.

## Code layout & conventions

- `src/` layout built with `uv_build`; the importable module is `pyroll.core`. `pyroll` is a **namespace package** (no `src/pyroll/__init__.py`) so that plugin packages can share the `pyroll.*` namespace — do not add an `__init__.py` there.
- Relative imports are banned (ruff `flake8-tidy-imports`); always import absolutely, e.g. `from pyroll.core.data_model import ...`.
- Line length 120. Ruff rule sets: E, F, UP, B, SIM, I.
- Core dependencies: numpy, shapely 2, pydantic 2 and `pyroll-pydantic-extensions` — the data model is expected to be built on pydantic.
- Tests live in `tests/`, mirroring the package layout (`src/pyroll/core/data_model/units.py` → `tests/data_model/test_units.py`).
- Commit messages follow the conventional commits standard.

## Documentation (`docs/`)

`docs/` is a technical reference for developers and AI, not the published docs site (that lives in a separate repository).

- `docs/architecture.md` — overview of the v4 architecture.
- `docs/adr/` — Architecture Decision Records, chronological.
- `docs/specs/` — feature specs from which features and tests are to be derived.

Files in `adr/` and `specs/` are sequentially numbered: `0001-some-short-title.md`. Consult the relevant specs/ADRs before implementing a feature, and record significant architectural decisions as a new ADR.
